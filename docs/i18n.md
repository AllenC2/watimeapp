# Plan de idiomas (es / en)

El selector de **Preferencias → General → Idioma** ya guarda `prefs.language` (`es` | `en`). Falta usarlo de verdad. El catálogo está en [`lib/i18n/messages.js`](../lib/i18n/messages.js).

## Enfoque

1. **Sin librería extra.** Un `t(key, vars)` que lee el diccionario según `prefs.language`.
2. **Una clave por texto de UI**, interpolación `{nombre}`.
3. **Fechas y horas** con `Intl` y locale `es-MX` / `en-US` (ya hay `hourClock` y `timezone`).
4. **APIs:** devolver `error` como clave (`errors.contactNameRequired`) o traducir en el cliente con esa clave. El catálogo incluye ambos lados.
5. **`document.documentElement.lang`** = `es` o `en` al aplicar preferencias.
6. **No traducir** nombres de usuario, contenidos de mensajes, plantillas, identificadores ni el logo.

## Orden de implementación

1. Exponer `t` y `locale` desde `PreferencesProvider` (lee `prefs.language`).
2. Sustituir literales en componentes, de fuera hacia adentro: Sidebar, Agenda, Nuevo mensaje, Configuración, Preferencias, WhatsApp, Contactos, Historial, Plantillas.
3. `CalendarView` / `HistoryPanel`: meses, días, Hoy/Ayer, estados.
4. `timeZoneMeta` y CSV (`Nombre`/`Identificador`, `contactos.csv`).
5. `getWhatsAppState`: `statusLabel`, `phoneLabel` vacío, plataformas.
6. Errores de API: o `Accept-Language`, o códigos + `t('errors.*')` en el cliente.

## Interpolación

`Por: {name}`, `Se borraron {count} mensajes`, `Ya existe como {name}`, `Quitar {name}`.

## Helpers

- `translate(messages, language, key, vars)` — fallback a `es` si falta la clave.
- `htmlLang(language)` → `es` | `en`.
- `dateLocale(language)` → `es-MX` | `en-US`.

En el provider, algo así:

```js
const t = (key, vars) => translate(messages, prefs.language, key, vars);
```
